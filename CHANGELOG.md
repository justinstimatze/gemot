# Changelog

All notable changes to gemot are documented here.

## Unreleased — DARPA Track 1 M8 work

### New Features

- **EigenTrust reputation + cold-start cap**: new `internal/analysis/eigentrust.go` implements the Kamvar/Schlosser/Garcia-Molina (SIGIR 2003) power-iteration eigenvector over a sparse directed trust graph with leaked-rank correction and a teleport-weighted pre-trust vector. New `internal/reputation/Weigher` composes this with persistent per-agent state (`agent_reputation`, `agent_trust_edges` tables) to produce multipliers for the `text.go` effective-weight chain. The cold-start cap clamps agents with fewer than `GEMOT_EIGENTRUST_COLD_THRESHOLD` (default 5) survived-round validations to at most `GEMOT_EIGENTRUST_COLD_CAP` (default 0.1); graduation is non-decreasing within a single cohort call (not globally monotone — cohort composition shifts the normalization denominator). Edges accumulate after each round from qualified-vote agreements filtered by crux survival; `AgreeAgents` are deduped per crux and self-endorsement is dropped. `survived_count` requires ≥2 distinct non-self agreers per round, which blocks 2-Sybil pair graduation but not larger rings — the graduation-cliff limitation and the five companion Planned-Defense rows (reputation decay, pubkey-bound identity, edge-table pruning, fail-closed DB toggle, per-delib privacy) are disclosed honestly in THREAT_MODEL.md. The global eigenvector is recomputed + persisted synchronously at round close via batched `unnest`-backed UPSERTs, eliminating the per-row transaction loop that was a lock-contention amplifier on large cohorts. Primary Sybil defense is the cold-start cap — canonical EigenTrust under a uniform teleport does not defeat closed trust cycles without OOB-trusted seeds, and hosted-mode Gemot has no such bootstrap set. Opt-in via `GEMOT_EIGENTRUST_ENABLED=true`. Schema bumped to version 2.
- **TLA+ specification of the deliberation protocol**: new `specs/Deliberation.tla` models the protocol state machine — round progression, position submission, qualified voting, commitment lifecycle, termination — with the LLM analysis step treated as an external oracle per the abstract's §3 design. Safety properties (append-only positions/votes, commitment lifecycle, Closed absorbing, no honest equivocation, no double-vote) and liveness (eventual termination under `WF(StartAnalysis) + SF(AnalysisClose)`) are mechanically checked by TLC 2.19 on OpenJDK. Matching `Deliberation.cfg` checks the minimal model (4 agents, 1 Byzantine, 12,675 distinct states) in ~3s with no errors. The initial liveness check found and fixed a real bug in the fairness annotation — `WF(AnalysisClose)` admitted an `Open → Analyzing → AnalysisFail → Open → …` lasso that `SF(AnalysisClose)` closes. `specs/README.md` documents the n-agent generalization argument (projection + cutoff) and bound rationale. Matches abstract §3 cross-cutting + §5 M16 TLA+ line.
- **Durable nonce cache for multi-instance envelope verification**: new `auth.PostgresNonceCache` (internal/auth/pg_nonce_cache.go) backs the envelope replay defense on the `envelope_nonces` Postgres table. Observation uses `INSERT ... ON CONFLICT DO NOTHING` so concurrent replicas converge on a single winner without distributed locking; a background janitor sweeps expired rows on a `ReplayWindow` cadence. Selected at startup by `GEMOT_NONCE_STORE=postgres`; defaults to the existing `MemoryNonceCache` for single-instance deployments. Closes the open THREAT_MODEL row that blocked horizontal scaling with `GEMOT_ENVELOPE_MODE=required`.
- **Cross-family OOD consistency check**: new `internal/llm/secondary.go` adds a Gemini-backed `SecondaryStructuredOutput` client (REST against `generativelanguage.googleapis.com` with `responseSchema` structured output) and a `SecondaryFunc` adapter used by tests. `TextAnalyzer` gains `SecondaryLLM` + `SecondarySampleK` fields plus a `SetSecondary` setter; the previously stubbed `validateAnalysisModelConsistency` is replaced with a real implementation that samples the top-K highest-controversy cruxes by `ControversyScore`, re-scores each agent's stance on the secondary against their latest-round position, and emits `CROSS_FAMILY_DRIFT` warnings when strict majority of agents on a given crux flip sign between primary and secondary. This is the §3 abstract defense against stable-but-wrong single-family outputs — "adversarial inputs can produce stable-but-wrong outputs that defeat variance-based ensemble detection." The warning is informational, not a refusal gate; training-distribution independence between frontier labs is imperfect (shared benchmark corpora, convergent RLHF) and that caveat is recorded in THREAT_MODEL. Off-by-default; opt in with `GEMOT_CONSISTENCY_MODEL` + `GEMOT_CONSISTENCY_KEY` (or `GEMINI_API_KEY`). Cost scales linearly with `GEMOT_CONSISTENCY_SAMPLE_K` (default 5) — ~5 Gemini-Flash-tier calls per analysis, single-digit cents on current pricing.
- **Fail-closed reputation DB toggle**: `reputation.Weigher.WeightsFor` now returns `(map[string]float64, error)`. Under the new `GEMOT_EIGENTRUST_DB_FAIL=closed` mode, a `LoadReputation` failure propagates through `TextAnalyzer.Analyze` and aborts the analysis round rather than silently degrading to unit weights. The default remains `open` (fail-open, preserves availability and legacy behaviour) but hosted / Byzantine-context deployments should opt in — otherwise an attacker who can DoS Postgres strips the cold-start enforcement exactly when it is needed. This is the concrete mitigation the Byzantine adversarial suite flagged as missing: the cold-start cap is the load-bearing Sybil defense, so a silent neutralization path is a single-point-of-failure. Mirrors the `GEMOT_ENVELOPE_MODE=required` fail-closed pattern. Config field `EigenTrustDBFail` plumbs through `main.go`; THREAT_MODEL.md row moved from planned → implemented.
- **Reputation decay + negative signals**: new `store.DecayTrustEdges` applies `weight *= 0.5^(age / halfLife)` to `agent_trust_edges` rows older than one hour inside `Weigher.recomputeGlobalScores`; one-hour skip prevents double-decay across back-to-back rounds. New `store.ApplyDisputeEdges` ingests per-dispute negative-weight rows via the same `unnest`-backed UPSERT pattern, allowing stored weight to go negative — EigenTrust clamps non-positive edges to zero at input (see `internal/analysis/eigentrust.go:142`), so an overt dispute cancels an endorsement of equal magnitude but does not punch trust below zero. `Weigher.UpdateFromRound` gains a `disputes []types.Dispute` parameter (breaking for in-tree callers only — three test files updated); it maps each dispute's `CruxClaim` to the surviving crux's source-position authors and emits `{From: disputer, To: author, Weight: DisputeWeight}` negative edges, skipping self-disputes and disputes that don't match any crux in the round. Schema bumped to version 3 (new `disputes.rep_processed_at` column); `store.GetUnprocessedDisputes` + `store.MarkDisputesProcessed` provide once-only ingestion semantics so a dispute contributes exactly once across rounds. Closes the whitewashing gap documented in the previous EigenTrust graduation-cliff disclosure: pumped Sybil-ring edges now fade on the half-life clock, and honest participants can counter-balance mutual-endorsement attacks by filing disputes. Both knobs off-by-default: `GEMOT_EIGENTRUST_DECAY_HALFLIFE_DAYS=0` disables decay; `GEMOT_EIGENTRUST_DISPUTE_WEIGHT` defaults to 0.5 but is only consulted when `Dispute` rows exist. Residual limitation: `survived_count` (the graduation side of cold-start) is still monotone-increasing — pubkey-bound reputation identity (companion Planned-Defense row) is the complementary fix for identity-transfer whitewashing.
- **Edge-table retention + per-edge weight cap (DARPA Track 1 Priority 3)**: `store.DecayTrustEdges` gains a `floor float64` parameter; after the existing decay UPDATE it runs `DELETE FROM agent_trust_edges WHERE weight > 0 AND weight < floor` to prune rows whose decayed weight dropped below the floor. Negative-weight dispute rows are retained unconditionally so persistent dispute signals can't get reabsorbed by a fresh endorsement without the history visible. `store.AccumulateTrustEdges` gains a `cap float64` parameter and clamps cumulative per-edge weight via `LEAST(agent_trust_edges.weight + EXCLUDED.weight, $cap)` in both the INSERT and the ON CONFLICT DO UPDATE branches — a Sybil pair that repeats mutual endorsement across many deliberations can push a single `(from, to)` edge to at most `cap` × unit endorsement instead of unbounded growth. Cap is intentionally NOT applied to `ApplyDisputeEdges`; disputes accumulate arbitrarily negative (EigenTrust already clamps non-positive edges at input, so extra-negative rows are harmless and preserve the dispute history). Two new env knobs, both off-by-default for legacy parity: `GEMOT_EIGENTRUST_EDGE_FLOOR` (default 0, recommended 0.01) and `GEMOT_EIGENTRUST_EDGE_CAP` (default 0, recommended 10.0). `reputation.Config` gains `EdgeFloor` + `EdgeCap` fields plumbed through from `config.Config`. Interface changes on `reputation.Store`: `AccumulateTrustEdges(edges, cap)` and `DecayTrustEdges(halfLife, floor)` — in-tree only, no external callers. Bounds `agent_trust_edges` row count under long-running operation (prune) and bounds per-edge damage under sustained Sybil mutual-endorsement (cap). `LoadTrustEdges` still returns the full graph; subgraph loading from the active cohort is tracked in THREAT_MODEL as the next performance ceiling.
- **Fix hallucinated-participant-ID regression in crux synthesis**: `extractParticipantIDs` (text.go:1956) was looking for `speaker="N"` attributes but `formatClaimsForCrux` (text.go:1878) emits `participant="N"`, so the extracted list was always empty and the resulting `{{PARTICIPANT_IDS}}` prompt substitution injected `""` instead of the real participant allowlist — leaving the LLM free to invent participant IDs in `agree`/`disagree`/`no_clear_position`/`stances` fields. The one-character fix (`speaker` → `participant` in the regex) restores the allowlist. Latent bug: `formatClaimsForCrux` switched emission attributes at some point without updating the regex, and there was no test pinning the contract. New `internal/analysis/participant_ids_test.go` (2 tests) pins the emitter↔extractor contract so a future drift fails loudly rather than silently.
- **Per-deliberation privacy boundary (MVP, DARPA Track 1 Priority 4)**: deliberations created with `visibility="private"` now opt out of the global trust graph entirely. `service.Analyze` skips `reputation.UpdateFromRound` + `GetUnprocessedDisputes` at round close when `d.Visibility == "private"` — private-delib agreement patterns neither emit edges into `agent_trust_edges` nor increment `survived_count`, so confidential coordination cannot leak into the globally-readable trust graph. `visibility="link"` is explicitly treated as public for reputation (discoverable-by-token, not consent-limited), so link-shared delibs still participate in global reputation. Tradeoff documented: in the MVP, private delibs neither contribute to nor benefit from reputation weighting — full per-delib private EigenTrust (partitioned edges keyed by `deliberation_id` + separate eigenvector) is tracked in THREAT_MODEL as a follow-up. No schema change required: the existing `deliberations.visibility` column already carries `open`/`private`/`link` values, and the existing ACL system already gates access to private delibs. No new env knobs. Reuses `deliberations.visibility` rather than introducing a parallel `is_private` column to keep the truth-source single.
- **Full per-delib private EigenTrust (DARPA Track 1 Priority 4 FULL)**: schema v5 partitions `agent_trust_edges` by a new `deliberation_id TEXT NOT NULL DEFAULT ''` column with PK `(from_agent, to_agent, deliberation_id)`. Rows with `deliberation_id=''` are GLOBAL edges (open/link delibs feed the globally-visible eigenvector); rows with `deliberation_id=<uuid>` are PRIVATE edges scoped to that one deliberation. `store.AccumulateTrustEdges` + `ApplyDisputeEdges` + `LoadTrustEdges` gain a `delibID` parameter so the reputation layer can write to a scoped partition and read `(from, to) IN ('' OR <delibID>)` for private-delib recomputes. `reputation.Weigher.UpdateFromRound` gains `delibID string` + `isPrivate bool` parameters; private rounds emit scoped edges, skip `IncrementSurvivedCounts` (so a private-ring Sybil graduation attack cannot pump `survived_count`), and skip the global eigenvector recompute. `Weigher.WeightsFor` reads `types.DelibFromContext(ctx)` and computes per-delib EigenTrust on-the-fly over the scoped partition union'd with the global graph — the private cohort sees the global trust landscape as prior (so a seasoned agent carries their reputation in) plus intra-delib patterns, but never another private delib's edges. Cold-start cap stays load-bearing: `survived_count` is global, and private rounds don't increment it, so fresh Sybils coordinating inside a private ring cannot cold-start out of the cap. MVP skip at `service.go:1275` removed — the service now always calls `UpdateFromRound`, threading `deliberationID` + `(d.Visibility == "private")` through. New `types.DelibContext` + `types.WithDelibContext` / `types.DelibFromContext` helpers (placed in `types/delibctx.go` to break what would be a `deliberation → reputation → analysis → deliberation` import cycle). Rolling-deploy caveat: the v5 PK change from `(from, to)` to `(from, to, delib_id)` is NOT rolling-safe; a ~30s maintenance window is required because machine-1-on-v5 drops the old PK and machine-2-on-v4 code would then error on `ON CONFLICT (from_agent, to_agent)`. Accepted at current deployment scale.
- **Pubkey-bound reputation identity**: schema v4 migrates the reputation vertex from symbolic `agent_id` to a namespaced form — `"key:<agent_keys.id>"` for agents with an active registered key at emission time, `"id:<agent_id>"` otherwise. New `store.ResolveVertices(ctx, agents)` method returns per-agent vertex strings via one batched `unnest` + `LEFT JOIN agent_keys` query; `LoadReputation` invokes it internally so callers still pass symbolic names. `Weigher.UpdateFromRound` pre-resolves every symbolic agent appearing in the round (crux authors, agreers, dispute filers) and emits edges against the resolved vertices, so edges are pinned to the key active at write time — a later rotation cannot retroactively transfer attribution. New `store.VertexKeyPrefix` and `store.VertexIDPrefix` constants expose the reserved-prefix convention; the `Store` interface adds `ResolveVertices` so the in-memory test fake and the Postgres implementation share the contract. Defeats the rename attack: re-registering an existing `agent_id` under a new pubkey yields a new `agent_keys.id`, a new vertex, and cold-start reputation — the incoming principal cannot inherit the prior key's score. Legit key rotation is symmetric (rotation = reset), which is the correct defense against a compromised K1 transferring trust to a freshly-registered K2 under the same symbolic name. Unsigned deployments are unchanged: all vertices fall back to `"id:<agent>"` and behaviour matches v3. Transition semantics: registering a key for a previously-unsigned agent forks the identity into a new key-bound vertex; the prior `"id:"` row remains in the DB but is orphaned because there is no cryptographic attestation that the unsigned history belongs to the new key. One-time migration cost: pre-v4 `agent_reputation` and `agent_trust_edges` rows are **deleted** on schema bump — a clean-slate transition is safer than in-place PK rewriting under rolling deploy (where machine-1-on-v4 writes and machine-2-on-v3 writes would collide on primary key when the migration UPDATE fires). Production gemot had no deployed reputation state at time of bump; demo and test runs regenerate reputation organically. Config-free — key binding activates automatically when signatures are present; no new env knobs.
- **HotStuff SMR session 3 — real BLS threshold sigs (DARPA Track 1 Byzantine-tolerant sequence agreement, session 3 of N)**: replaces the sessions-1/2 `PlaceholderSigner` with real BLS12-381 multi-signatures via `github.com/consensys/gnark-crypto@v0.20.1`. New `internal/bft/bls_signer.go` (~200 lines) implements the `Signer` interface on top of gnark-crypto's BLS12-381 primitives: `Sign` computes `s·H(msg)` on G1 with RFC 9380 hash-to-G1 under DST `BLS_SIG_BLS12381G1_XMD:SHA-256_SSWU_RO_NUL_`; `Verify` runs `PairingCheck([-H(msg), sig], [pk, g₂])`; `Aggregate` sums per-replica G1 points into a single 48-byte aggregate regardless of signer count; `VerifyAggregate` sums the listed signers' G2 public keys and runs one pairing check. Duplicate signers in `VerifyAggregate` rejected. Each replica owns an independent keypair — **this is BLS multi-signature, not threshold BLS**, intentionally: multi-sig matches HotStuff's QC data model exactly (QC carries the explicit `Signers` list so the verifier derives the aggregate public key by summing those signers' PKs) and avoids the DKG dependency that threshold BLS requires. Threshold / DKG is session-5 territory (alongside multi-node key distribution). Library choice finalized: gnark-crypto's curve primitives (G1/G2 arithmetic, pairing, hash-to-G1) are clean and the crypto-dependency graph grows by only one module beyond what gnark-crypto itself pulls. Verified `CGO_ENABLED=0 go build ./...` passes — pure-Go, matches the Fly Dockerfile posture; rules out herumi/bls-eth-go-binary and supranational/blst. Candidates considered and rejected: circl/sign/bls (full BLS API but VerifyAggregate takes distinct-message pairs, suboptimal for same-message HotStuff QCs); drand/kyber-bls12381 (has threshold primitives we don't yet need). New test file `internal/bft/bls_signer_test.go` exercises 7 unit tests: sign/verify roundtrip, tampered-sig rejection, wrong-signer rejection, aggregate roundtrip at 2f+1, duplicate-signer-in-VerifyAggregate rejection, aggregate-verify-rejects-wrong-message, keypair-roster-mismatch-rejection at constructor. `PlaceholderSigner` + `NewPlaceholderSigner` deleted from `signature.go` — only the `Signer` interface and `newViewDigest` helper remain (digests are message-layer, orthogonal to the signing scheme). `newCluster` test helper generates a fresh BLS keyset per cluster and distributes matched (keypair, roster) pairs to each replica; all 13 protocol tests (9 session-1 happy-path + 4 session-2 adversarial) pass under real pairing-based verification with the expected ~200ms runtime cost (up from ~3ms under placeholder). `specs/hotstuff-design.md` promotes real-sigs from deferred to delivered with the scheme details + multi-sig-vs-threshold distinction documented; `THREAT_MODEL.md` sub-caveat updated. **Still deferred**: service-layer integration + durable Postgres log (session 4), multi-node Fly deploy + HTTPTransport + real wall-clock timer + client QC proof (session 5), replica-key distribution via trusted setup or DKG (session 5), formal `<>[]progress` liveness property in TLA+. Commit is additive — no schema change, no service change, no prod deploy required; `internal/bft/` remains not wired into `internal/deliberation/service.go`. Dependency bump: `go` 1.25.0 → 1.25.9 (required by gnark-crypto v0.20.1's `go >= 1.25.7` floor).
- **HotStuff SMR session 2 — view change (DARPA Track 1 Byzantine-tolerant sequence agreement, session 2 of N)**: extends `internal/bft/` with the canonical HotStuff view-change protocol, preserving safety under Byzantine leader failure. **Go protocol additions**: new `Replica.Timeout()` constructs a domain-0x03-signed `NewView(view+1, highQC)` and broadcasts it to all peers; new `Replica.HandleNewView(nv)` verifies the sender signature and the carried highQC (via `verifyQC`, rejecting forged-QC NewViews with `ErrBadNewViewQC`), accumulates per (targetView, sender) in a new `pendingNewViews` map, and on 2f+1 collection selects the highest-view QC among the collected set and stores it in `viewChangeHighQC` for the new leader. `Propose` transparently substitutes `viewChangeHighQC[r.view]` for the caller-supplied `(parent, justify)` so post-timeout proposals automatically extend the correct branch — callers don't need to distinguish happy-path vs post-view-change. `HandleVote` now calls `processJustify` on the formed QC so the leader integrates its own output into highQC (without this, a post-vote timeout would carry a stale highQC and undermine the view-change selection rule). New error sentinels `ErrStaleNewView`, `ErrBadNewViewSig`, `ErrBadNewViewQC`. New digest domain byte `0x03` for NewView signatures, separated from vote (`0x01`) and proposal (`0x02`) so a real BLS scheme in session 3 cannot replay one domain's signature as another. **TLA+ spec additions (specs/HotStuff.tla)**: new state variables `newViews` (set of `[sender, view, highQCblock]` messages) and `timedOut` (`[Replicas -> SUBSET Views]`); new actions `TriggerTimeout(r, claimedQC)` (Byzantine can claim any QC'd block as highQC, modeling stale-NewView attacks without signature forgery) and `ViewChange(v)` (advance global view when 2f+1 NewViews exist for `v`); new liveness branch in `HonestCanVote` (vote for `b` if `b.parent.view > BlockOf(locked[r]).view`, even if `b` doesn't extend `locked[r]` — without this, view change would leave honest replicas locked on the pre-timeout branch forever); new invariant `NewViewQCIsReal` pinning the no-forged-QC threshold-sig assumption; new temporal property `ViewMonotonic` (view counter never regresses); `NewViewsMonotonic` for NewView append-only-ness; `FormQC` hardened with `v = view` guard on the view-advance clause so belatedly-formed stale-view QCs cannot regress the global view counter. Tight cfg (`HotStuff.cfg`: MaxView=2, MaxBlocks=3) explores ~14,000 states in ~2s; stress cfg (`HotStuff_stress.cfg`: MaxView=3, MaxBlocks=3) explores ~537,000 states in ~10s — both pass all safety invariants. **Adversarial test suite (internal/bft/adversarial_test.go, 4 new tests)**: `TestLeaderStall` exercises the canonical view-change flow — leader of view 1 silent, replicas 1/2/3 timeout, new leader (replica 1) collects 2f+1 NewViews and proposes in view 2 with QC forming normally; `TestLeaderEquivocatesAcrossViews` confirms safety under a Byzantine leader that broadcasts conflicting blocks to different subsets — neither block accumulates 2f+1 votes so no QC forms and no honest replica commits a height-1 block; `TestPartitionedMinority` confirms non-progress when only 2 replicas participate (sub-quorum NewView count does not populate `viewChangeHighQC`), and the progress-on-heal path once a third replica rejoins; `TestStaleNewView` verifies the highest-view selection rule — after a happy-path view-1 QC plus a partial view-2 proposal that propagates the QC into honest replicas' highQCs, two honest timeouts + one Byzantine-forged NewView carrying a stale genesis highQC result in the new leader selecting the real view-1 QC, not genesis. All 9 existing session-1 tests continue to pass; total 13 tests in `internal/bft/` running in ~3ms. **Docs**: `specs/hotstuff-design.md` promotes view change from deferred to delivered and updates the deferred list to sessions 3+ (real BLS, service integration, durable log, multi-node deploy, client proof, formal temporal liveness); `specs/README.md` adds session-2 invariants + properties + Byzantine model expansion; `THREAT_MODEL.md` "Byzantine-tolerant sequence agreement" row sub-caveat updated to reflect view-change + adversarial tests shipping with remaining deferrals listed. **Still deferred**: real threshold signatures (session 3 swaps PlaceholderSigner for BLSSigner via gnark-crypto), service-layer integration + durable Postgres log (session 4), multi-node Fly deploy + real wall-clock timeout timer + client-side QC proof verification (session 5), formal `<>[]progress` liveness property in TLA+ (deferred until bounds permit TLC liveness-check in budget). Commit is additive — no schema change, no service change, no prod deploy required; `internal/bft/` remains not wired into `internal/deliberation/service.go`.
- **HotStuff session 1 — review-driven fixes (same commit series)**: adversarial review of the session-1 drop caught a meaningful spec-vs-impl disconnect plus several medium-severity code gaps. Fixes applied before downstream work. **Spec tightening**: `LockOn` was an optional TLA+ action with no fairness, so TLC explored executions where honest replicas never locked; `ExtendsChain(b.id, locked[r])` with `locked[r]=genesis` is trivially satisfied, meaning the spec allowed honest replicas to vote for conflicting blocks across views. At the original tight bounds the violation wasn't reachable; at `MaxView=4, MaxHeight=2, MaxBlocks=5` TLC finds the explicit counterexample — `r0` commits `{0, 1, 3}` with blocks 1 and 3 both at height 1. Fix: couple the honest-replica lock update into `FormQC` atomically so every honest replica's `locked` advances monotonically on QC formation. Removed the optional `LockOn` action (now redundant). Re-verified at both tight (`HotStuff.cfg`, 510 states, <1s) and stress bounds (new `HotStuff_stress.cfg`, `MaxView=4`, 62,017 states, ~5s). The stress cfg is retained as a regression harness. **Proposal signature verification**: `HandleProposal` now rejects proposals whose `Sender` is not the designated leader for the proposal's view (`ErrWrongLeader`) and verifies the proposal's signature against that leader (`ErrBadProposalSig`). Without these checks, any entity with transport access could inject proposals claiming to be the leader — session-1 happy-path tests wouldn't have caught it because the harness is trusted. **Digest domain separation**: vote and proposal digests are now prefixed with distinct domain bytes (`0x01` vote / `0x02` proposal) so a signature over `(view, blockhash)` cannot be replayed across message types under a real threshold-sig scheme. **Double-propose guard**: `Propose` now refuses to emit a second proposal in the same view (`ErrDoublePropose`). The session-1 test harness doesn't exercise this, but it's the leader-side mirror of `lastVotedView`. **`commitBlock` chain-gap refusal**: if an ancestor is missing from `knownBlocks`, commit is refused rather than creating a gap in `committedLog`. Prevents `CommittedChainConsistent` violation under session-2 log-replay. **`pendingVotes` GC on `AdvanceView`**: buckets from strictly prior views are dropped so a long-running replica doesn't accumulate memory from views that never reached quorum. **`HandleProposal` ordering**: move `knownBlocks[h] = block` after the safety check so unsafe proposals leave no residue. **`PlaceholderSigner` replica-ID width**: encoded ID moved from 1 byte to 4 bytes (big-endian uint32); the 256-replica cap silently folded larger IDs under modulo. **Leader rotation**: changed from `view % N` to `(view-1) % N` so view 1 picks `roster[0]` rather than `roster[1]` — conventional form, doesn't affect safety. **Cleaned `TestHappyPathSingleCommit`**: deleted the smoke test with stranded dev-comments and no assertions; coverage preserved by `TestHappyPathCommitsAfterFourRounds`. **Three new tests** in `internal/bft/protocol_test.go`: `TestDoubleProposeBlocked` (leader refuses second proposal in same view), `TestWrongLeaderRejected` (non-leader sender rejected), `TestBadProposalSigRejected` (tampered signature rejected).
- **HotStuff SMR session 1 (DARPA Track 1 Byzantine-tolerant sequence agreement, partial)**: new `internal/bft/` package implements the chained-HotStuff protocol core — `types.go` defines Block/QC/Proposal/Vote/NewView message types; `state.go` holds per-replica state (view, lockedQC, highQC, preparedQC, lastVotedView, knownBlocks, committedLog) under a per-replica mutex; `protocol.go` implements `HandleProposal` / `HandleVote` / `Propose` / `AdvanceView` with the HotStuff §4 safety rule (vote iff block extends lockedQC OR justify.View > lockedQC.View) and the two-chain commit rule (QC on child C whose parent B has `C.View == B.View + 1` triggers commit of B); `signature.go` provides `PlaceholderSigner` wrapping a `byte(ReplicaID) || sha256(msg)` pseudo-signature that is EXPLICITLY non-cryptographic — session-2 work wires real threshold signatures via a pure-Go BLS library (gnark-crypto preliminary choice, enforced by the Fly Dockerfile's `CGO_ENABLED=0` posture which rules out herumi/bls-eth-go-binary and supranational/blst); `transport.go` defines the `Transport` interface plus `InMemoryTransport` (channel-backed, for tests) and an `HTTPTransport` stub that returns errors on every method so accidental use is caught immediately.
